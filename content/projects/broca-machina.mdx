My research is split between the wet lab and computation. A model trains on one cluster while
an analysis runs on another. Much of that work needs a decision from me while I am at the bench
with gloves on, running a gel or checking the mouse colony. However, every way of
reaching the computational side assumed free hands and a keyboard. I built broca-machina so
that the work continues through conversation.

broca-machina gives a text model a voice in a Discord voice channel. It transcribes what I say,
passes the text to my assistant, and speaks the reply. The assistant routes each request to the
agent that should do the work (the training run, the analysis) and answers the rest itself. The
name comes from Broca's area, the region of the left frontal lobe involved in speech production.

The same channel serves the bench. I document an experiment while I run it, log a new litter or
a cage change for the colony, and ask a troubleshooting question when a step fails, all of it
hands free.

Speech runs on the GPU in my desk machine, but the answers come from cluster jobs that can take
a minute. A minute of silence on a voice call reads as a failure. A small local model therefore
speaks a short, relevant "acknowledgment" 3.5 seconds after I stop talking, and the real answer
follows when it lands.

## The assistant hears me by default, and any session can take over

Saying "connect me to" and a session's name routes my voice straight into that session, and one
phrase returns it to the assistant. The second model takes typed requests only.

## A request takes six steps from speech to answer

1. **Listen.** broca joins the channel and records only the speaker it was told to hear. A voiceprint check stops it from answering anyone else.
2. **Transcribe.** A warm faster-whisper server turns the clip into text on the local GPU.
3. **Decide whether it was addressed.** A wake word passes at once, and so does anything said right after a reply. The small local model judges the rest: was I talking to the bot, or to someone in the room?
4. **Deliver.** The text goes to the brain. Here the brain is my assistant, a Claude Code session, and broca reaches it as an MCP channel.
5. **Acknowledge.** If the answer is slow, the small model speaks a short line tied to what I asked.
6. **Speak.** broca strips the markdown from the reply and speaks it a sentence at a time, so the first words play while the rest is still being written.

## The bridge runs locally, and the brain is one small interface

- Transcription (faster-whisper) and the voice (Kokoro or Piper) run on the local GPU. No audio goes to a cloud speech service.
- I can interrupt it mid-sentence. A short noise only ducks the volume, real speech stops playback, and the brain learns what I did not hear.
- It runs under Discord's end-to-end voice encryption, which most voice libraries cannot negotiate yet. That requirement is why it runs on Bun.
- The brain is a small interface. The same bridge drives a one-line `echo` toy or a full agent, over files, a command, or an MCP server for a host like Claude Code.

## Setup needs a bot token, ffmpeg and a Python environment

```bash
bun install
cp config.example.json config.json   # discord ids, stt, tts, transport
bun src/voice_loop.js config.json
```

The Python environment carries faster-whisper and Piper; the repo's `SETUP.md` covers the
rest.
